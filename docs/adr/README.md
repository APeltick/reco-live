# Решения проекта (ADR)

Решения «как и почему», которые переживут один change: архитектура, данные, правила кода. Поведение продукта — не здесь, а в спеках OpenSpec (`openspec/specs/`).

- **Решение** — файл `ADR-NNNN-<slug>.md`: «как решено сейчас». Шаблон — `0000-template.md` (полный; без вариантов — минимум, как сказано в нём).
- **История** — `history/<тот же файл>`: записи «дата · автор · принято | изменено | отменено», новые сверху; в записи «изменено» — почему и полный прежний текст.
- **Номер один навсегда.** Решение поменялось — правится тот же файл и запись сверху в истории; другой вопрос — следующий номер (`ai-team adr-next`). Отменённое остаётся со своим номером, статус «отменён»; «Superseded» и замены новым файлом нет.
- ADR, которые проект вёл раньше по стандарту (`NNNN-<slug>.md`, Accepted / Superseded), остаются как есть; правка такого ADR — перевод его в шаблон.

Индекс ниже собирает скрипт — `ai-team adr-index` (или `node .github/ai-team/process-guard.mjs adr-index --write`); руками не править, конфликт в git не сводить, а пересобрать. Формат и правила — spec/13 AI kit.
