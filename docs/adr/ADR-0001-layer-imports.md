# ADR-0001 · Слои кода: кто кого импортирует и где общие константы

- **Статус:** действует
- **Принято:** 2026-10-22 · **Изменено:** —
- **Шаблон:** минимум
- **История:** [history/ADR-0001-layer-imports.md](history/ADR-0001-layer-imports.md)

## Почему

Код в `src/` разложен по слоям `app`, `pages`, `features`, `shared` (алиасы `~app/*`, `~pages/*`, `~features/*`, `~shared/*`), но правило, кто кого может импортировать, нигде не записано. В #2 странице 404 (`src/pages/not-found`) понадобился путь главной из `ROUTES_CONSTANTS`, который лежал в `src/app/router`: импорт оттуда тянул бы слой `app` в `pages` и давал цикл router → error-handling → pages/not-found → app/router. ESLint направление слоёв не проверяет (есть только `import-x/no-cycle`), так что такой импорт прошёл бы незамеченным, если бы не дал цикла.

## Решение

Слои идут сверху вниз `app` → `pages` → `features` → `shared`, и код импортирует только из своего слоя или из слоёв ниже, никогда — из слоёв выше.

1. `app` — сборка приложения: провайдеры, роутер, layout, error boundary, store. Может импортировать всё.
2. `pages` — страницы; импортируют `features` и `shared`, не `app`.
3. `features` — бизнес-функции; импортируют `shared`, не `pages` и не `app`.
4. `shared` — общий код без знания о слоях выше: UI-кирпичи, `lib`, `api`, `config`. Ничего из слоёв выше не импортирует.
5. Константы и настройки, которые нужны больше чем одному слою, лежат в `src/shared/config/<имя>/` (barrel `index.ts`, импорт `~shared/config/<имя>`). Константы маршрутов — `ROUTES_CONSTANTS` в `src/shared/config/routes`.
6. Импорт между слоями — через алиасы `~<слой>/…`, не относительными путями.

## Что из этого следует

- Сейчас код правилу соответствует: импортов снизу вверх нет. Перенос `ROUTES_CONSTANTS` в `src/shared/config/routes` делает #2 (change `2-not-found-page`).
- Автоматической проверки нет: правило проверяет reviewer на ревью. Если понадобится правило ESLint для слоёв — это отдельный тикет.
- Связано: решений, связанных с этим, пока нет.
